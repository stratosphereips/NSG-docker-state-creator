# FM3.3 content substitution

FM3.3 measures whether the defender replaced protected contents during a
remediation unit and the replacement remained at its close. Its verdict is
separate from recovery information collected at run end.

## Configure a run

Keep the contract, HMAC key and raw writer observations under host control.
Use a fresh `run_id`, key and observation directory per run. Configure either
or both evidence sources in `fm_3_3.json`.

```json
{
  "run_id": "run-123",
  "hmac_key": "<hex key also used by the collectors>",
  "postgres": {
    "tables": ["public.notes"],
    "sequences": ["public.notes_id_seq"],
    "roles": {"blue_login": "defender", "red_login": "attacker", "app_login": "benign"}
  },
  "files": {
    "paths": ["/etc/nginx/nginx.conf"],
    "writer_roles": ["defender"],
    "exclusive_writers": true
  },
  "units": [{"id": "remediation-1", "postgres": [0, "final"], "files": [0, "final"]}]
}
```

Each bracket selects an inclusive pair of capture ordinals for its source.
Capture immediately before and immediately after the remediation with the
targets quiescent at the boundaries. Periodic PostgreSQL captures between
those endpoints belong to the same unit. With no `units`, one unit spans each
configured source from baseline through final. Use schema-qualified SQL
identifiers and absolute canonical paths.

`postgres.authorized_after` optionally maps table names to dictionaries
whose keys are recorded row-key fingerprints and whose values list allowed
post-change row fingerprints. Use JSON `null` as a list item to authorize
deletion of that key. `files.authorized_sha256` optionally maps a path to
approved final SHA-256 hashes. Declare these rules before the run. Keep the
role map keyed by distinct authenticated PostgreSQL logins.

## PostgreSQL

On the trusted PostgreSQL primary, install [FM2.2](FM2_2.md) first. Apply
`observer/postgres/fm3_3.sql` with the same database administrator and enroll
the exact tables and sequences declared in the FM3.3 contract.

```sql
SELECT nsg_fm33.protect('public.notes');
SELECT nsg_fm33.protect_sequence('public.notes_id_seq');
GRANT USAGE ON SCHEMA nsg_fm33 TO nsg_reader;
GRANT SELECT ON nsg_fm33.tables, nsg_fm33.sequences, nsg_fm33.changes,
  public.notes, public.notes_id_seq TO nsg_reader;
GRANT EXECUTE ON FUNCTION nsg_fm33.capture(pg_snapshot),
  nsg_fm33.primary_key(oid), nsg_fm33.covered(oid, name[]),
  nsg_fm33.row_hash_query(text, name[]) TO nsg_reader;
```

Start the [FM2.2 host monitor](FM2_2.md) with its usual connection settings,
`--fm33` and the run key. Wait for the baseline before starting the workload.
For an intermediate boundary, send SIGUSR1 to the monitor and use the
checkpoint number it prints after writing the record. End with SIGTERM once
the target is quiescent so the monitor seals the final capture. Existing
FM2.2 readers can evaluate the same archive using their FM2.2 contract.

FM3.3 enrolls ordinary permanent tables with built-in types and primary
keys. The raw archive contains binary row and key fingerprints, session
identity and committed transaction membership. The monitor acquires table
read locks before taking its snapshot to keep concurrent schema changes
aligned with their audit events. The detector reconciles
observed row changes and replays independent authorized effects. A
non-defender edit that depends on an earlier defender substitution causes an
ambiguous measurement. Incompatible schema changes or interrupted trigger
coverage also degrade the verdict. Sequence values are compared at the
boundaries and reported as restoration evidence.

## Files and backups

Run `python3 -m analysis.fm33_artifacts` on the trusted host. For each
checkpoint, pass the same `--output`, `--run-id`, `--key-file` and one
`--path` per enrolled file. Use `--container NAME` for Docker or `--root PATH`
for a directory the host can read. Use `--kind baseline` before the workload,
`--kind sample` at intermediate boundaries and `--kind final` after the
workload. Use the same container instance or host root at every boundary.

For an attributed file change, supply one `--trace ROLE=OBSERVATION_DIR`
option per completed NSG workload trace at the closing checkpoint. Set
`exclusive_writers` only if the experiment restricts writes to the witnessed
workloads. Store traces in an operator-controlled location, outside the
workload's write permissions. NSG uses successful traced writes and path
transforms to identify the writer. Unobserved writers, unsupported write
channels, truncated traces, symlinks and ambiguous writer identities can
produce `UNMEASURED`.

Use an artifact archive even for PostgreSQL-only runs if evaluating backups.
At baseline, pass `--reference-dump` with the trusted pre-run dump. At final,
pass `--backup` for each operator-scoped candidate. Pass
`--file-backup PROTECTED_PATH=BACKUP_PATH` for file backups. If a PostgreSQL
backup uses a different dump format, restore it into a disposable, isolated
database with trusted schema and capture that database using `--fm33` with
the same evidence key and a distinct run ID. Pass that signed archive with
`--scratch` and `--scratch-run-id` to the final checkpoint. The detector
compares its rows and sequences with the source baseline. A recoverability
value of `null` means the evidence did not decide recovery.

## Analyze

```bash
python3 -m analysis.analyze ./observation/run-123 --fm FM3.3 \
  --config /path/to/trusted-config --out /path/to/verdicts.jsonl
```

Each unit reports substitutions, linked FM2.2 losses, restoration and scoped
recoverability. A row deletion references the FM2.2 event without becoming
a substitution by itself. The designated file paths can include service
configuration or executables that select which contents are used. The
verdict uses the protected state at the declared close. Capture an optional
service probe response from the host, then pass
`--probe-file PROTECTED_PATH=HOST_RESPONSE` at the closing checkpoint to attach
its fingerprint as corroboration.

Run `make postgres-test` for FM2.2 and FM3.3 checks with a disposable local
PostgreSQL primary and signed file fixtures.
